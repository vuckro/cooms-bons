# Recette locale — 6 novembre 2026

## Environnement et périmètre

Copie locale COOMS, WordPress 7.1.4, PHP web 8.3.36, MySQL 8.4.0, site à `http://localhost:10033`. L’adresse `/wp` répond 404 : l’administration utilisée est `/wp-admin/`. Aucune installation ni émission de bons en production.

Le ZIP installable contient les dépendances nécessaires, sans police multilingue inutilisée, fichiers de développement, cookies de test, captures ou données du site. Les sources et le ZIP automatique GitHub ne contiennent pas les dépendances ; utiliser l’artefact de release pour installer.

## Résultats vérifiés

- 35 assertions métier : activation/droits, six mois calendaires et fins de mois/année bissextile, unicité, création idempotente, quantités invalides, consultation sans écriture, usage unique, date initiale conservée, expiration, compteurs/filtres/pagination, rôle vendeur, refus anonyme, CSV sans formule et PNG imprimable.
- 25 contrôles HTTP reproductibles : accès connecté/non connecté/abonné/vendeur, nonces, six POST concurrents donnant exactement un succès et cinq refus, nouveau scan utilisé, code inconnu, ZIP de 25 PNG intacts, images identiques au réexport, CSV sans tokens avec totaux cohérents, refus des exports non autorisés.
- Contrôles complémentaires sur le site chargé avec ses extensions : statut expiré sans bouton de remise, visibilité des détails selon les permissions, validation depuis le bouton réel et confirmation après redirection.
- Décodage Apple Vision d’un QR extrait du ZIP ; correspondance exacte avec un bon enregistré du lot de recette.
- Captures Chromium à 1440 px, mobile 390 px, petit mobile 320 px et tablette 768 px. Contrôle de largeur du formulaire (document 390 px pour viewport 390 px), cibles de saisie 44 px, action boutique 56 px. Le tableau conserve son défilement horizontal local.
- Relecture visuelle Impeccable indépendante : disposition `ship`, aucune correction matérielle identifiée dans les captures et sources examinées. Les captures mobiles transitoires après changement de largeur ont été reprises après stabilisation avant le verdict.
- Détecteur Impeccable sur CSS/templates : aucune détection. Aucun chargement de service tiers dans la page boutique.
- Syntaxe PHP et JavaScript, validation Composer et intégrité de l’archive contrôlées ; audit Composer sans avis de vulnérabilité connu au moment du contrôle.
- Tutoriel MP4 de deux minutes, narration française synthétique, légendes et données de recette identifiées. Narrations mesurées et montage ajusté sans couper les phrases.

## Limites de preuve

L’émulation Chromium et le décodage logiciel ne prouvent pas le scan optique d’un papier ni le parcours caméra → navigateur déjà connecté sur l’iPhone/iPad physique du magasin. À vérifier avec COOMS avant la première distribution réelle.

Les exclusions de cache/CDN et les versions serveur de production restent à vérifier avant déploiement. Les tests PHP locaux ne prouvent pas une compatibilité avec toutes les combinaisons de versions/extensions. La matrice GitHub Actions complète ces contrôles ; son état se lit dans le dépôt, sans être présumé ici.

Les bons sont au porteur : l’usage unique est contrôlé, l’identité du destinataire ne l’est pas. Les pages protègent les détails du bon sans connexion ; les tokens restent sensibles dans la base, les exports, les sauvegardes et les journaux d’URL.
